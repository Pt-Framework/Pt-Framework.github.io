Detailed Description

WebSocket is the client side of a WebSocket upgrade. It performs the HTTP handshake through an HTTP user agent and then sends and receives payloads on the stream that handshake produces. Host, port, event loop, timeout and TLS are settings of that agent. The handshake uses the client's timeout. The socket stores a reference and does not own it, so the agent must outlive the socket, including a handshake that is still waiting on the loop. After a finished 101 the socket formats the stream the client already owns. setIdleTimeout() bounds inbound silence, setPingInterval() a keepalive ping after inbound silence, setPingTimeout() an unanswered ping, and setCloseTimeout() a close handshake the peer never answers. The client still owns the connection. Closing the socket closes the stream. The socket does not own the stream. A client masks every frame it writes.

The example completes the handshake and then writes a text message.

void onOutputReady(Pt::Http::WebSocket& socket)
{
Pt::Http::MessageProgress progress = socket.endSend();
if( ! progress.finished() )
socket.beginSend();
}
void onInputReady(Pt::Http::WebSocket& socket)
{
Pt::Http::MessageProgress progress = socket.endReceive();
if( ! progress.finished() )
{
socket.incoming().discard();
socket.beginReceive();
return;
}
socket.incoming().clear();
socket.beginReceive();
}
void onConnected(Pt::Http::WebSocket& socket)
{
socket.endConnect();
socket.outgoing().setType(Pt::Http::WebSocketMessage::Text);
socket.outgoing().body() << "hello";
socket.beginSend();
socket.beginReceive();
}
Pt::System::MainLoop loop;
Pt::Net::Endpoint ep("localhost", 80);
Pt::Http::Client client(loop, ep);
Pt::Http::WebSocket socket(client);
socket.connected() += Pt::slot(onConnected);
socket.outputReady() += Pt::slot(onOutputReady);
socket.inputReady() += Pt::slot(onInputReady);
socket.beginConnect("/ws");
loop.run();

Construct the socket with the Client that performs the handshake. Connect connected() and call beginConnect() with a request path, or with a ws:// URL whose host and port are already the client's endpoint. The path and query of that URL become the request URL; the client does not take the host from the URL. The optional second argument is the Origin header. endConnect() completes the handshake and throws if it failed. addProtocol() offers one Sec-WebSocket-Protocol name before beginConnect(). Several calls offer several names, in order. After a finished handshake protocol() is the single name the server echoed, or empty when the server selected none. An echo that was not offered fails the handshake. After that success the socket no longer uses the client for messages.

The socket owns two WebSocketMessage objects, incoming() and outgoing(), the way a client owns a request and a reply. Set the type, write the body, and call beginSend(). Call beginSend(false) while more body will be written, then beginSend(true) for the last part. outputReady() reports that data bytes were sent. endSend() returns MessageProgress. If the send step is not finished, beginSend() continues it with the same completion flag. beginReceive() fills incoming(). inputReady() reports that data bytes were received. endReceive() returns progress. After finished(), clear() drops the body so the same object can carry the next message. beginReceive() starts frame processing. Until then, incoming frames stay in the stream. Control frames are processed while a receive is outstanding. A local beginShutdown() also keeps input running until the peer replies with its close frame. The two are independent: a receive started before or during a shutdown still delivers what the peer sent before that reply.

Ping, pong, shutdown and close are socket operations, not messages.

socket.beginPing();
socket.beginShutdown(1000, "done");
socket.close();

beginPing() enqueues a ping. pingReady() reports that its frame was written; call endPing() from that signal to observe a write error. A received ping is answered by the engine. After a close frame is queued nothing further is written, so beginPing() throws and a received ping is no longer answered. A received pong is reported by pong(). Neither is delivered through incoming(). beginShutdown() enqueues a close frame with a status code and a reason, then keeps reading until the peer replies. shutdownReady() reports the completed handshake; call endShutdown() from that signal to observe an error. A peer that never starts a receive never replies, so setCloseTimeout() bounds that wait. It defaults to ten seconds. Zero leaves the wait unbounded. setPingInterval() writes a keepalive ping after inbound silence. setPingTimeout() bounds that ping and an unanswered beginPing(). Interval, ping and idle default to zero on this type. A received close is answered by the engine. When no local shutdown is outstanding, closed() reports that the protocol has ended. The stream stays bound. Call close() from that signal. An outstanding shutdown completes through shutdownReady(); call endShutdown() and then close(). beginReceive() and beginShutdown() then throw. closeCode() and closeReason() report the handshake that ended the stream. No close frame leaves the code at 1006. close() releases the stream and writes no frame. It does not block and emits nothing. The destructor calls it. Destruction of the stream detaches the channel. The owner deletes this socket.

On the server the application does not construct this type. The server facade is WebSocketSession, which exposes the same message operations without a client handshake.

◆ setPingInterval()

void setPingInterval ( std::size_t ms)

Zero disables the interval. Incoming data, a received ping, and a received pong restart it. Sending does not. The engine writes an empty ping only while a receive is outstanding. That ping does not emit pingReady(). beginPing() throws while a ping is outstanding. setPingTimeout() bounds the wait.

◆ setPingTimeout()

Zero disables the ping timeout. The wait starts at beginPing() and at a keepalive ping. A pong stops it. An incoming ping does not.
